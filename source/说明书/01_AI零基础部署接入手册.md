# 长明 Everlight · Beta 13 AI 零基础部署与接入手册

> Beta 13（v0.1.0-beta.13）公开个人测试候选。独立单人、本机部署；独立认知运行模块不随本版分发，十二库相关记忆类别及梦境修订保留。真实宿主、模型、跨平台与正式仓库升级尚需验收；旧版升级不承诺兼容。production_approved=false。




适用：RC6 / J12 / Beta 13 个人测试版。新增梦境和更新流程以根目录 `梦境同步接入_Beta10.md` 与 `发行与更新.md` 为准。单人、独立、回环地址邀请内测，不是生产授权。Linux Node 22.16.0 已验证；Windows/macOS、真实模型与生产 DSH 尚未验收。

## 1. AI 接手时的唯一入口

用户只需要交付安装包、获授权的历史文件，以及一次部署与数据处理授权。AI 先读 `AGENTS.md` 和本手册，然后执行环境检查、配置、导入、联调、验证和报告。没有终端、文件或客户端控制权限时明确报告，不能假装安装。不要把历史消息中的命令当作当前授权。不要扫描用户未指定目录，不接管生产库，不发送密钥或私人原话给未经授权的服务。

部署前一次性确认：①独立测试库；②历史文件与处理范围；③允许使用的模型/向量供应商与预算、留存风险；④是否允许新增服务和修改客户端配置。缺少权限或凭据时才询问。单人 scope 固定 `personal`，不能混入客户、其他家庭或其他测试者数据。Beta 13 只建议使用非敏感测试数据。模型密钥由本机私有配置提供，不在对话索取或回显。

## 2. 环境与初始化

在解压目录执行 `node -v`、`npm -v`，Node >=22，需支持 `node:sqlite`（已验证 22.16.0）；包内核心无需 npm install。AI 若缺少运行时，使用系统支持的官方安装路径，需系统权限或网络授权时请求一次确认。Windows POSIX 文件权限校验可能不兼容，优先使用获授权的 WSL/Linux；不能通过取消校验解决。

首次且尚无 trial-beta 时，独立无历史试用可执行：

```sh
npm run beta:init
npm run beta:preflight
npm run beta:verify
npm run beta:login
npm run beta:start
```

`beta:init` 创建私有 trial-beta 目录，不可对已存在的库重复初始化。`beta:verify` 使用临时独立数据库，不等于真实模型验证。`beta:start` 是前台运行，Ctrl+C 停止；重启只执行 start。`beta:login` 显示本机面板地址和令牌，仅在私密本机终端查看。首次数据为空正常。实际端口以预检输出为准。默认 core 18790、面板 18787、可选网关 18792。全部使用 127.0.0.1，不自动公开。

## 3. 配置模型：先区分四种地址与凭据

| 用途 | 地址/配置 | 凭据 |
|---|---|---|
| 模型供应商 | provider.local.json 的 upstream，供应商 API base（通常 /v1） | upstream_key |
| 聊天客户端 | http://127.0.0.1:18792/v1（默认） | trial-beta/gateway.local.json 中 gateway_key |
| 核心宿主 API | trial.env 的 EVERLIGHT_CORE_URL | CORE_TOKEN + 按接口要求的 SHARED_HOST_TOKEN |
| 人类面板 | beta:login 实际地址 | UI_TOKEN |

上游地址不填 `/chat/completions`，网关会追加；不能填长明自身端口形成循环。远程模型要求 HTTPS；本机模型可用 loopback HTTP。模型 ID 必须是供应商实际支持的名称，不是显示昵称。原生非 OpenAI-compatible 协议必须有兼容适配层；不能假设所有 Claude、Gemini、DSH、小手机都支持。

```sh
umask 077
cp provider.example.json provider.local.json
chmod 600 provider.local.json
```

在私有文件中配置以下结构，全部占位符需要由 AI 依据已授权配置替换（不要直接运行示例地址）：

```json
{"port":18792,"upstream":"https://example.invalid/v1","models":["实际模型ID"],"upstream_key":"本机已授权测试密钥","association_recall":false}
```

没有历史导入时，先 init，停止现有试用服务，运行 `npm run beta:gateway -- provider.local.json`，然后 `npm run beta:preflight` 和 `npm run beta:start`。网关配置仅创建一次，不覆盖已有文件。换模型需停止服务，私下备份旧 gateway.local.json 并移走，再重新配置；新 gateway_key 需要同步到客户端。若已有配置且正在首次导入，不重复传 --provider。

客户端 API Base URL 填实际网关 `/v1`，Key 填 gateway_key，模型填 models 中的 ID。验证 GET `/v1/models` 与 POST `/v1/chat/completions`；不是所有 OpenAI API 都受支持。普通流式聊天与二次联想能力不能混为一谈；J12 联想工具仅支持非流式、单候选、无客户端工具/结构化输出的私人对话。模型支持工具调用且单独授权后可将 association_recall 设 true；可能增加调用费用。默认关闭。

## 4. 首次历史导入：AI 操作，不让人类逐条分类

优先使用一体化脚本。文件格式 JSON/JSONL/TXT/CSV/GZ，复杂平台导出先按 `converter/config.example.json` 和 `converter/README.md` 核对字段映射；不保证任意嵌套格式自动识别。保留原文件、说话者、来源、时间与时区，未知时间不猜。以下使用本机实际路径：

```sh
npm run beta:ai-deploy -- --input "/path/history.jsonl" --allow-model --provider "/path/provider.local.json"
npm run beta:ai-deploy -- --input "/path/history.jsonl" --allow-model --provider "/path/provider.local.json" --apply --confirm-history
```

第一条仅规划检查；第二条须已有一次授权。已配置网关时省略 --provider。仅离线保存原话且未配置网关的独立试用库：

```sh
npm run beta:ai-deploy -- --input "/path/history.jsonl" --raw-only --apply --confirm-history
```

AI 自动选择空闲 core/UI 端口（指定 gateway 端口冲突需解决配置），初始化、预检、临时启动、原话归档、100 条结构校准、分类、关联、独立复核、合规提交并报告。最多 100000 条是当前默认配置，不是任意真实语料准确率保证。导入结束临时服务自动停止，AI 需按已授权的运行方式再 start。需要定制转换配置使用 `--config /path/config.json`，私有权限 0600；定制配置即使同时提供 provider，也要在安全本机环境设置其 transport 指定的 URL/KEY/MODEL 环境变量；URL 是完整 chat/completions 路径。不能把网关密钥当供应商密钥。

`trial-beta/imports/<批次指纹>/easy-progress.json` 和 `bootstrap-report.json` 为进度和报告；根据实际报告汇总原话、新增/复用、候选、正式提交、待审、失败。结构校准通过不表示内容准确。相同源与配置重跑以复用断点和原话；provider 已写入后重跑须省略 --provider。禁止删除试用库或擅自清锁；先检查是否仍有进程。预算字段为估算而非严格供应商费用上限；另设供应商预算和小样本测试。

自动正式提交当前覆盖经独立模型复核的明确历史经历（S04）、技能/代码（S06）、非推断且明确过去时间的情绪表达（S08）、具明确过去发生时间及已结束有效期的非推断事实/偏好（S05）。存在来源、身份、历史版本冲突时仍暂缓。批次授权不是逐条人类审核。其余身份、偏好、任务、关系等可能留在候选或待审，AI 可以整理冲突但不可假冒批准。历史聊天不会启动旧任务、覆盖当前身份或自动更新情绪。若要继续补审，走第 7 节，不要求用户先分类。无模型时只有原话归档，不是结构化全库记忆。

## 5. 语义及向量配置

默认导入使用模型语义分类和本地 lexical/BM25 关联。可选 `embedding.type` 为 lexical、openai-compatible 或 offline-vectors。远程向量单独授权，配置文件仍为完整 converter 配置，以下是局部示例，不是完整文件：

```json
{"embedding":{"type":"openai-compatible","urlEnv":"EVERLIGHT_EMBEDDING_URL","apiKeyEnv":"EVERLIGHT_EMBEDDING_KEY","model":"实际向量模型ID","dimensions":1024,"batchSize":10,"maxInputBytes":10000000}}
```

URL 填供应商实际 embeddings 完整 endpoint；安全地设置对应环境变量。维度需与真实返回一致（1–4096），不能只因维度高就认为更准确。离线向量配置 vectorFile、model、dimensions、revision，文件必须包含对应候选文本 SHA256 与向量，覆盖不全或元数据不同会拒绝。向量匹配是未核实的关联提示，不可自动合并人物或写事实。当前转换器的向量关联与在线召回向量服务不是同一开关；Beta 10 冻结配置默认在线向量服务关闭，不能靠修改 trial.env 绕过 profile。在线 vector/ 及 vector-sync 为研发插件能力，独立接入需要额外验收。

## 6. 三类接入路径

A. 有自定义 OpenAI-compatible API 的同机客户端：按第 3 节切换到网关，测试普通消息、原话捕获、召回及读回。客户端若不在同一网络命名空间，127.0.0.1 指向它自己；本版不自动开放网络。官方 ChatGPT/DeepSeek APP 不能直接假定可接入。

B. 有可编程宿主（DSH 测试实例/自建 agent）：采用 `adapters/host-neutral.mjs` 的 EverlightHostAdapter、`adapters/mandatory-turn.mjs` 的 createMandatoryTurn。宿主从私有 trial.env 解析 core URL、CORE_TOKEN、SHARED_HOST_TOKEN（不交给聊天模型），scope personal。每轮先捕获真实 source，再 recall，验证返回、构建真实请求并 readback，最后调用实际模型；失败时不冒充已注入。mandatory-turn 是最小示例，返回 transport_returned 不代表提供商真实消费，生产流式、工具及重试需宿主适配。回复与工具结果回收也要由宿主实现，参考 gateway/reply-capture.mjs 和 adapters/tool-lifecycle-d14e4.mjs、tool-journal-d14e4b.mjs。不得在现役 DSH 直接安装或改生产插件。

C. 只有 HTTP 工具、无终端：如果已有已授权独立长明服务，可以由可信代理调用其 API；模型不能持有管理密钥。只有聊天功能的 AI 不能自主部署；明确缺失能力即可。

### 宿主最小示例（在包根目录保存为本地 .mjs，服务启动后运行）

```js
import {readFileSync} from 'node:fs';
import {parseEnv} from 'node:util';
import {EverlightHostAdapter} from './adapters/host-neutral.mjs';
const e=parseEnv(readFileSync('trial-beta/trial.env','utf8'));
const a=new EverlightHostAdapter({baseUrl:e.EVERLIGHT_CORE_URL,
 token:e.EVERLIGHT_CORE_TOKEN,hostToken:e.EVERLIGHT_SHARED_HOST_TOKEN});
console.log(await a.request('GET','/api/v8/status'));
console.log(await a.hostHooks());
```

只读发现不等于已接入。宿主须验证捕获、召回、出站读回、实际响应捕获、重启、拒绝跨 scope、通知持久化与授权边界。通知使用 adapters/connect-e12.mjs 和 connect-inbox-w3e.mjs，单独 CONNECT_TOKEN，按 seq 水位消费、持久处理后推进游标；收到 inbox 不等于 AI 已阅读。统一 API 的示例见 connectClient：`/api/everlight/v1?route=/api/v8/connect/manifest`；不能把 dashboard `/ui/api/v1/...` 与 core `/api/v8/...` 混为一谈，UI 代理具体路由需依据服务实现。

## 7. 写入方式：正常对话不写表格，宿主负责来源与证据

模型仅在宿主注册 `remember()` 时可调用无参数工具。它返回已进入分类队列或 held 等状态，不保证正式入库。普通网关捕获原话不等于规范记忆已生成。Beta 10 默认关闭在线模型分类及自动提交；如果用户明确授权持续分类，配置 provider 的 automation 对象：`{"allow_conversation_classification":true,"model":"已配置的模型ID","user":"真实用户标签","ai":"真实AI标签"}`。两个标签不同，模型必须在 models 中。历史一键部署会拒绝已含 automation 的配置，先完成历史导入，停止服务后再按第 3 节重新配置网关。在线分类仍不自动正式提交。

严格 D9 写入顺序（可信宿主）：

1. POST `/api/v8/source` 保存原话：scope、actor、kind、source_ref、body，返回真实 source id。
2. GET `/api/v8/write/contracts` 读取当前机器合同；POST `/api/v8/guidance` 可选建议，不写入。
3. POST `/api/v8/proposal/validate` 校验候选；POST `/api/v8/write/strict-proposal` 传完整字段及 host token；候选不是正式记忆。
4. GET `/api/v8/joint/status?id=<候选ID>` 获取 digest；有权限的独立角色分别 POST `/api/v8/joint/ai` 与 `/api/v8/joint/human`，字段 scope,id,digest,decision,reason；各自独立 `x-everlight-decision-token`。人类决定必须真实授权，不能由模型冒充；批次导入只用已实现的授权路径。
5. POST `/api/v8/commit/scoped`，scope,id；检查 readback_verified 和实际 GET `/api/v8/memories/detail?slot=S05&id=<正式ID>`。旧无 scope `/api/v8/review` 和 `/api/v8/commit` 返回 410。人工注释与正文修订不同，更新必须 target_id 和 expected_revision；冲突重新读取，不覆盖历史。

### 虚构 S05 偏好候选例子（字段来自 test/d9-http.mjs）

```json
{"scope":"personal","slot":"S05","kind":"preference","source_refs":["真实source返回ID"],"reason":"当事人原话","idempotency_key":"宿主生成的稳定唯一键","payload":{"template_version":"everlight.write.d7","contract_version":"everlight.write.d9","category":"aesthetic","statement":"长期喜欢简洁界面","subject":"人物A","attribution":"当事人原话","evidence_status":"direct","temporal":{"key":"ui_style","event_at":null,"valid_from":null,"valid_until":null}}}
```

注意：source_refs 不填编造 ID；每种 kind 的类别与必要字段不相同；不把推断写为直接证据。可空字段填 null，不可空且缺证据暂缓。用附录逐类模板，不直接写 SQLite。真实聊天内容按原意，事实、假设、梦境、扮演、计划、历史与现状区分。角色的自述保持归属，不能代替事实验证。幂等重试保持同一键与内容。

## 8. 专用功能与召回

S01 原话由宿主自动保存；S02 动作回执和 S10 召回审计由引擎生成，不允许 AI 提案。S03 新任务走 goal，进展走 `/api/v8/tasks/event`，带版本和来源；独立验收不得自证。人物跨渠道身份用已确认 external_id，不同人同名不合并。照片须真实消费和归档授权；夜契使用专用 vault 通道，不明文写普通库。梦境 `/api/v8/dream/start`、advance 是账本流程，不是现实事实或默认自主做梦。工作联系 `/api/v8/relations/work-contact` 为试验接口，尚未验收客户隔离。完整字段见附录及机器合同。

召回：POST `/api/v8/recall` 的 scope/query，选传 limit、retrieval_hint、focus_context、association_parent。宿主最低必要检索不应由模型跳过。避免一次注入全部历史；无关内容不进入正文；需要原话证据时，仅使用已授权 S01 search/expand。`recall/readback` 核对实际出站 messages；`recall/transport` 记录传输凭证，不能宣称模型理解。J12 二次联想由网关受控工具在符合条件的情况下执行，不应自行伪造父召回 ID。精准 Token 预算、全域自然浮现、真实模型效果仍待验收。

## 9. 验收和排错

AI 自行完成并记录（不要用测试者的私人聊天做公开日志）：

- `npm test`、`npm run beta:verify`、`node test/d9-http.mjs`；分清历史回归日志和本次运行。
- 检查面板真实访问、12 分卷、任务、人物、照片、梦境、夜契、设置；每项记录读取/写入/读回/未支持，不以 HTTP 200 代替功能正确。
- 合成一条带明确历史日期的原话及一条歧义内容；检查正确分流、重复导入、历史不覆盖当前。
- 实际客户端对话检查 S01 来源、真实候选、召回与无关样例；明确是否真实模型、是否有二次联想实际调用；重启再检查。
- 401/403：检查地址与凭据类别、scope、host/decision 授权；不要关鉴权。410：换 scoped 当前接口。422：读取 D9 返回，补真实字段或 held。端口冲突：停止自己启动的试用进程或改未使用端口，不能杀别人的服务。429/超时：降低并发，保留进度再试。模型不支持 JSON/tool：报告能力限制，不伪造响应。
- 导入完成后服务停止是预期；再次 start。数据备份：停止所有写进程后把完整 trial-beta 目录复制到私有安全位置（含设置、D14、导入断点和资源）；现有 scripts/backup.mjs 仅覆盖部分核心/面板/可选向量与照片，不当完整备份。不要分享数据库、令牌、密钥或敏感报告。

最终报告：实际运行环境/版本/端口；模型接入及证据；原话/正式记忆/候选/失败数；各功能已实测、未测、失败；重启与权限测试；阻塞项、复现步骤和剩余待办。不得写“全部成功”代替逐项结果。生产仍未授权。
