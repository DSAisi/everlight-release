# Beta 10 联动验收与操作手册（本次修订）

## 给新手 AI：先理解四种状态

1. 已保存：面板设置写入 settings.sqlite 或 UI 数据库并读回。
2. 已排队：事件进入核心收件箱，可能还没有消费者。
3. 宿主已接收：可信宿主持久化处理并提交 receipt；不代表模型已读。
4. 请求读回/执行结果：宿主保存实际模型请求和响应来源；仍需实际读回正式数据才能认定任务完成。

不要向人类逐个询问如何操作。部署前只确认安装和数据处理范围、模型服务授权、必要凭据。缺少宿主能力时报告，不模拟唤醒。

## 开关对照表

| 界面 | 默认/配置条件 | 保存及实际影响 | 提醒/验收 |
|---|---|---|---|
| 持续状态与自动关心 continuity | 独立配置开启 | `EVERLIGHT_H6_CONTINUITY` + 设置库；已结束或过期状态不能当现状 | 设置静默同步；实际到期跟进需宿主消费 |

| 质量核查调度 repair | 默认配置开启 | `EVERLIGHT_W1_QUALITY_NUDGE` + 设置库 | 核查任务与设置同步是两种事件 |
| 召回资源策略 | 自动；最低检索不能关闭 | 当前面板是状态展示，非每通道开关；二次联想由网关配置 | 不因查看状态唤醒 AI |
| 做梦 | 无全局自动唤醒开关；默认 legacy auto=0 | 面板邀请写共享事件；空闲机会由宿主传真实 idle/enabled | dream_request 是唤醒意图；真实宿主仍须接线 |

设置中心 GET/POST `/api/v8/ui/settings`，POST `{domain:"core",key:"memory",enabled:false}`（示例，只有实际授权才能改）；检查返回 core 项的 available、enabled、desired、effective。409 说明依赖/授权未配置；不要硬改 SQLite 或环境绕过。设置快照在核心 GET `/api/v8/connect/inbox` 时生成/合并，kind=settings、wake=false；不保证每次点击都产生独立事件。通知中心的“最近设置快照的宿主接收回执”显示宿主确认时间。关闭再开启后如最终状态未改变，允许合并。要主动联系 AI，使用通知中心留言按钮，而不是每个开关都唤醒模型。

## 宿主接线：实际执行模板

使用 `adapters/connect-runtime-w3e.mjs` 的 openConnectRuntime，或既有持久化消费者，不要重复起两个消费者争抢同一 scope。可信宿主从本地 trial.env 读取 CONNECT_TOKEN，独立保存 file/cursorFile 两个 SQLite 文件。直接核心 URL 时 receipt 需要显式 reportAcceptance:true；统一面板 URL 时 unified:true。启动 start({dispatch,intervalMs:3000,onError})；dispatch 回调必须先持久化并按 idempotencyKey 去重才能返回。以下是回调的**宿主伪代码**，`host` 是你真实实现的队列和执行入口，不是长明提供的对象：

```js
async function dispatch(event, {idempotencyKey, mode}) {
  if (event.kind === 'settings') {
    await host.persistLatestSettings(event.content, idempotencyKey);
    return; // sync，不唤醒模型；执行端重新读取有效配置
  }
  if (await dreams.handle(event, {idempotencyKey})) return;
  if (event.kind === 'action' && event.content?.target === 'everlight-update') {
    await host.enqueueMaintenance(event.content, idempotencyKey);
    return;
  }
  await host.dispatchExisting(event, {idempotencyKey, mode});
}
```

`dreams` 来自 dreamDispatch；详见根目录《梦境同步接入_Beta10.md》。没有对应的真实队列就先实现宿主适配，不要把空回调当成完成。对每个事件保留真实队列 ID；处理失败抛异常以便重试；宿主重启后继续处理未完成任务。设置事件不需要 shared/ack，使用 Connect receipt；主动提醒使用 shared/ack、delivery、resolve 区分接收、请求读回、实际结果。更新任务另用专用维护接口。普通 OpenAI-compatible 网关提供聊天捕获和召回，不等于具有后台唤醒、梦境任务消费或更新代理。

## 功能联动及测试顺序

- 设置：开/关 memory、查看 commitments effective；关后检查分类 worker 暂停，重新开启恢复；未配置时应拒绝。再轮询 inbox，检查最新 settings 快照及 receipt；不产生模型调用。
- 提醒：人类在通知中心提交，记录返回 ID，检查 inbox action/wake=true，宿主 durable enqueue，实际模型请求读回、响应来源、resolve；网络失败原键重试。普通更新/梦境邀请都是持久任务，不表示自动成功。
- 梦境：按钮 POST `/api/v8/ui/workflow` action=dream-invite + idempotency_key；GET `/api/v8/ui/dream-invitations`；两者由统一面板代理。宿主 `dream.opportunity({idle,enabled})`，只使用真实空闲和授权状态；24h 冷却，不强制做梦。九类自主选择见 DREAM_GUIDANCE；source_ids 为真实可用证据。advance 记录阶段不代替语义执行；revision 提交版本候选；improvement 提交 S11 假设；虚构梦不得修改真实记忆。按治理审核后 commit，读回 revision，重新召回验证。当前无自动批次梦境授权、无完整行为验证闭环。
- 照片：先开启授权来源，提交真实图片事件与视觉消费回复事件，再用 completed 上传二进制；检查图片读回、撤回及不允许重放。没有视觉能力的模型不得伪造回执。
- 夜契：只有明确授权私密频道，宿主检查 reminder，记录私密 evidence，再密封 capture。关闭授权后应拒绝；不要将明文作为普通 source 或发向未授权模型。
- 更新：仓库公钥、版本、备份、验签、停写、安装、健康、回滚逐项实测；无法确认完全停写时不得安装。详见发行与更新.md。
